# Hybrid fabric kinds

The platform runs one EVPN fabric per hub. Tenants get VRFs on it; sites attach through gateways.

| Kind | Namespace | Owner | Purpose |
|------|-----------|-------|---------|
| **HybridFabric** | `sovereign-cloud` | platform | Fabric ASN, VNI pool, underlay, border gateway VM |
| **CloudInfrastructure** | `sovereign-cloud` | platform | Cloud site; see [cloudinfrastructure.md](cloudinfrastructure.md) |
| **CloudGateway** | `sovereign-cloud` | platform | Attaches one site (CloudInfrastructure) to the fabric |
| **TransportLink** | `sovereign-cloud` | operator | Tunnel state for one CloudGateway; generated, not authored |
| **HybridNetwork** | `entity-<name>` | tenant | VRF: VNI + route target, allocated from the fabric |
| **NetworkPlacement** | `entity-<name>` | tenant | Places a HybridNetwork on a tenant cloud project with prefixes |

Order: HybridFabric → CloudInfrastructure → tenant Cloud* projects → CloudGateway → HybridNetwork → NetworkPlacement. The GitOps sync waves in `gitops/apps/platform-fabric` follow it: 20, 25, 30, 50/55, 60, 65.

Hosted clusters (PlatformOpenshift) do not join the fabric. A tenant cluster-admin controls the cluster's network stack and could inject routes into other tenants' VRFs.

## HybridFabric

```yaml
apiVersion: hybridsovereign.redhat/v1alpha1
kind: HybridFabric
metadata:
  name: platform-fabric
  namespace: sovereign-cloud
spec:
  enabled: true
  domainAsn: 65010
  entityRefs:
    - name: example-corp
  vniPool: {start: 51000, end: 52127}
  underlay:
    type: localnet              # or ovn-layer2 (default)
    physicalNetworkName: physnet
    nadName: fabric-localnet
    cidr: 192.168.64.0/18
    hubVtepBlock: 192.168.65.0/24
    hubLegAddress: 192.168.65.1/24
    mtu: 1400
  borderGateway:
    name: fabric-bgw
    loopback: 10.255.10.10
    wireguard: {address: 10.254.254.1/24, listenPort: 51820}
  bgp:
    authentication:
      secretRef: {name: fabric-bgp-auth}   # optional, key "password"
  transportDefaults: {mtu: 1442, defaultTunnelType: none}
```

`underlay.type`:

- `ovn-layer2` (default): the border gateway's underlay NIC is on an OVN-Kubernetes layer2 network without IPAM. It holds `gatewayAddress` and serves `dhcpRange`.
- `localnet`: the NIC is on an OVN-Kubernetes localnet network on the node bridge mapped to `physicalNetworkName` (`physnet` is `br-ex` by default). The gateway holds `hubLegAddress`, and hub nodes use addresses from `hubVtepBlock` as EVPN VTEPs. No DHCP is served, because it would answer on the node network. `hubVtepBlock` and `hubLegAddress` must lie inside `cidr` and require `localnet`.

Status: `ready`, `bgwEndpoint`, `bgwAddress`, `bgwPeerCount`, `allocatedVniCount`, `availableVniCount`, `peers[]{address,site,state,prefixesReceived}`, `conditions[]`.

## CloudGateway

```yaml
apiVersion: hybridsovereign.redhat/v1alpha1
kind: CloudGateway
metadata:
  name: example-oso-gw
  namespace: sovereign-cloud
spec:
  enabled: true
  fabricRef: platform-fabric
  cloudRef: {kind: CloudInfrastructure, name: example-openstack}
  transport:
    type: wireguard            # none | wireguard
  wireguard:
    address: 10.254.254.12/32  # allocated when omitted
  siteUnderlay:                # openstack sites only
    interface: enp7s0
    computeInterface: eth5
    cidr: 192.168.80.0/24
    gatewayAddress: 192.168.80.1
    mtu: 1442
  macNatShim:                  # test environments only
    enabled: false
```

The CloudInfrastructure type selects the gateway flavour: `openstack` builds a site gateway VM on the management cluster and rolls the EVPN configuration out to the data plane NodeSets; `openshift` lands the fabric on the hub nodes (transport `none`). The transport type is set only here. Region and ASN come from the CloudInfrastructure and the fabric.

Status: `ready`, `transportReady`, `peerState`, `vtep`, `importedRts[]`, `edpmNodeSets[]{name,fingerprint,deployment,state}`, `conditions[]`.

## TransportLink

Generated by the operator, one per CloudGateway; do not create or edit it. `spec.tunnelType` mirrors `CloudGateway.spec.transport.type`. Status: `tunnelUp`, `borderEndpoint`, `cloudEndpoint`, `lastHandshakeAt`.

## HybridNetwork

```yaml
apiVersion: hybridsovereign.redhat/v1alpha1
kind: HybridNetwork
metadata:
  name: example-core
  namespace: entity-example-corp
spec:
  description: Core VRF
  fabricRef: platform-fabric
  overlayMtu: 1300             # optional; computed from the fabric when omitted
```

Status: `vni`, `canonicalRt`, `vrfName`, `overlayMtu`, `placements[]{name,backendKind,backendName,prefixes,ready}`.

## NetworkPlacement

```yaml
apiVersion: hybridsovereign.redhat/v1alpha1
kind: NetworkPlacement
metadata:
  name: example-core-hub
  namespace: entity-example-corp
spec:
  network: example-core
  backend: {kind: CloudVirt, name: local-virt}   # CloudOSO | CloudVirt | CloudAWS
  prefixes: [10.110.2.0/24]
  vmNamespaces: [example-core-vms]                 # CloudVirt only
```

For a CloudVirt backend the operator creates the `vmNamespaces` on the hub (default: one namespace `<cloudvirt>-<network>`) and labels them at creation as primary-network members of the HybridNetwork, before any VM starts. A namespace joins one network only, and the operator refuses an existing namespace unless the same entity and CloudVirt own it. You cannot select existing namespaces by label. CloudVirt prefixes must not overlap the hub's cluster, service or node networks. Delete the placement to remove it.

Status: `ready`, `validated`, `realizedPrefixes[]`, `vmNamespaces[]`, `backendIds{}`, `vni`, `canonicalRt`, `cloudGatewayRef`, `conditions[]`.
